# 마케팅 1단계 — ASO + 해몽 사전 SEO 사이트 설계

- 작성일: 2026-10-05
- 상태: 사용자 승인(브레인스토밍) → 구현 계획 작성 전
- 범위: 마케팅 A안(검색 자산 + 바이럴 루프) 4개 하위 프로젝트 중 **1) ASO**, **2) 해몽 사전 SEO 사이트**.
  (3) 꿈 카드 공유 기능, (4) SNS 콘텐츠 자동 생성은 별도 스펙으로 이후 진행.

## 0. 전제

- 단계: 프로덕션 공개 직후, 3개월 1차 목표는 **초기 사용자 확보**.
- 예산/시간: **무료 + 주 몇 시간**. 사람 손은 검수·업로드·콘솔 입력만, 나머지는 자동화.
- 타깃 두 층:
  - 2030 여성(타로·운세 관심층) — 비주얼/SNS (이번 범위에선 스토어 전환율로만 대응)
  - 4060 해몽 검색층 — 네이버/구글 검색 → SEO 사이트
- 2026-10-05 기준 Play 검색 '해몽'(KR) 상위 15위 안에 Monkey 없음. 상위 앱 대부분 제목이 "꿈해몽"으로 시작.

## 1. 목표와 지표

| 지표 | 목표 |
|---|---|
| Play 검색 '해몽' 순위 | 4주 내 15위 진입, 8주 내 10위 진입, **3~6개월 내 1위**(장기) |
| Play 검색 '꿈해몽'·'꿈풀이' 순위 | 동반 추적(목표치 없음) |
| SEO 사이트 | 구글 서치콘솔 노출/클릭, 네이버 유입, Play `utm_source=seo` 설치 수 추적 |

순위는 관련성(메타데이터)만으로 오르지 않는다. 설치 속도·평점·리뷰 수·리텐션이 같이 필요하므로
메타데이터 + 인앱 리뷰 + 외부 유입(SEO)을 한 묶음으로 진행한다.

## 2. 섹션 1 — ASO + 인앱 리뷰

### 2-1. 메타데이터 교체 (Play Console 수동 입력, 단일 소스 `docs/release/store-listing.md`)

- **제목**: `꿈해몽 몽키 - 전통 해몽·꿈풀이·꿈일기` (22자 / 한도 30자)
  - '해몽'·'꿈해몽'·'꿈풀이'·'꿈일기' 커버. 브랜드는 한글 '몽키'.
  - Play 정책 금지 표현('1위', '무료', '최고', 이모지 등) 사용 금지.
- **짧은 설명(≤80자)**: 꿈해몽·태몽·길몽·꿈풀이를 자연스러운 한 문장에 포함.
- **자세한 설명(≤4000자)**: 전면 재작성.
  - '해몽'은 자연 문맥에서 6~8회. 키워드 나열·반복 금지(Play 스팸 정책).
  - 인기 상징("돼지꿈·뱀꿈·똥꿈·이빨 빠지는 꿈" 등)을 본문에 넣어 롱테일 대응.
  - 기존 고지(참고용, 미래 단정 아님)와 프라이버시 문단 유지.
- **스크린샷 캡션·피처 그래픽 문구**: `scripts/gen-store-screenshots.py`의 `SHOTS` 문구만 수정 후 재생성(전환율 목적).
- 변경하지 않음: 패키지명 `com.mswon.monkey`, 런처 표시명 "Monkey".

### 2-2. 인앱 리뷰 요청 (앱 업데이트 versionCode 5 / versionName 1.3)

- 라이브러리: `react-native-in-app-review` (Google Play In-App Review API).
- 트리거: 해몽 결과 **저장 성공 직후**, 누적 저장 횟수 ≥ 3이고 마지막 요청 후 90일 경과(또는 요청 이력 없음)일 때 1회.
  - 누적 저장 수 = SQLite `dream_diary` 행 수(삭제분 제외), 마지막 요청 시각 = AsyncStorage 키 `inAppReview.lastRequestedAt`.
  - 해몽 실패·오류 직후에는 호출하지 않음.
- 사전 질문 팝업·별점 유도 문구 없음(Google 정책). API 직접 호출만.
- API 미지원/실패 시 조용히 무시, 앱 흐름 비차단.
- 테스트:
  - 트리거 판단을 순수 함수(`shouldRequestReview({savedCount, lastRequestedAt, now, lastResultOk})`)로 분리해 Jest 단위 테스트.
  - 실제 다이얼로그는 Play 설치본에서만 뜨므로 내부 테스트 트랙에서 확인.

### 2-3. 순위 측정

- `docs/marketing/rank-log.md`에 주 1회 기록: 날짜, '해몽'/'꿈해몽'/'꿈풀이' 순위, Play Console 스토어 방문→설치 전환율, 유입 검색어, SEO 지표(섹션 3-6).
- 순위 확인은 Play 검색 페이지(`hl=ko&gl=KR`) 조회로 반자동화 가능.

## 3. 섹션 2 — 해몽 사전 SEO 사이트

### 3-1. 검색 행태 반영 (핵심 원칙)

실제 사용자는 "ㅇㅇ꿈 해몽"보다 **"~하는 꿈" 형태의 상황 문장**으로 검색하며, '해몽'은 붙일 때도 있고 아닐 때도 있다.
(예: "돼지가 집에 들어오는 꿈", "이빨 빠지는 꿈", "뱀한테 물리는 꿈 해몽")

따라서:
- **상황 페이지가 주력 랜딩**이다. 상징 페이지는 허브(상황 목록 + 상징 총론) 역할.
- 상황 페이지의 `<title>`·H1·URL은 **"~하는 꿈" 문장으로 시작**하고, '해몽'은 뒤에 보조로 붙인다.
  - title: `돼지가 집에 들어오는 꿈 해몽 — 전통 꿈풀이 | 몽키`
  - H1: `돼지가 집에 들어오는 꿈`
  - URL: `/haemong/돼지가-집에-들어오는-꿈/`
- 상황명은 검색창에 실제로 칠 법한 **구어 표현**(현재형 "~는 꿈")으로 생성한다.
- 같은 상황의 변형 표현(시제·어순·동의어: "돼지가 집에 들어온 꿈", "집에 돼지가 들어오는 꿈", "멧돼지가 집에 들어오는 꿈")을
  `aliases`로 함께 생성해 본문 소제목·문장과 meta description에 자연스럽게 녹인다(나열 금지).
- 상징 페이지 title은 `돼지꿈 해몽 — 돼지 나오는 꿈 모음 | 몽키` 처럼 "ㅇㅇ꿈"과 "ㅇㅇ 나오는 꿈"을 함께 커버.

### 3-2. 위치와 URL

- `docs/haemong/` → `https://ms-won.github.io/Monkey/haemong/` (기존 GitHub Pages, `main`의 `/docs` 서빙).
- 기존 `docs/index.html`(개인정보처리방침, Play 등록 URL)은 변경하지 않는다.
- 슬러그는 한글, 공백은 `-`. 슬러그 충돌 시 빌드 실패.

### 3-3. 파이프라인 (`scripts/seo/`, Python)

```
backend/dream_dictionary.json (77 상징, 근거 단일 소스)
   │  gen-situations.py  ── OpenAI gpt-4o-mini, 상징당 1회 호출
   ▼
content/haemong/<표제어>.json   (상징 총론 + 상황 3~5개, reviewed:false)
   │  ← 사용자 검수: 파일 수정 후 reviewed:true
   │  build-site.py
   ▼
docs/haemong/**  (정적 HTML + sitemap.xml)  → git push → Pages 배포
```

**콘텐츠 JSON 스키마 (`content/haemong/<표제어>.json`)**

```json
{
  "symbol": "돼지",
  "slug": "돼지",
  "polarity": "길",
  "summary": "상징 총론 (400~700자)",
  "situations": [
    {
      "title": "돼지가 집에 들어오는 꿈",
      "slug": "돼지가-집에-들어오는-꿈",
      "aliases": ["돼지가 집에 들어온 꿈", "집에 돼지가 들어오는 꿈"],
      "polarity": "길",
      "body": "상황별 해몽 본문 (400~700자, 단락 구분)"
    }
  ],
  "reviewed": false,
  "generated_at": "2026-10-05"
}
```

**`gen-situations.py`**
- 사전 항목(표제어·동의어·의미·극성·비고)을 근거로 상징 총론과 상황 3~5개를 생성.
- 상황 선정 기준: 해당 상징으로 사람들이 실제 검색할 법한 대표 상황 우선.
- 프롬프트 원칙(앱 백엔드와 동일): 전통 한국 해몽 정설 준수, 서양식·뉴에이지 해석 금지, 공포 연출 금지, 미래 단정 금지, 비고의 역몽/오해 포인트 반영.
- 출력은 JSON 모드로 받아 스키마 검증 후 저장. 이미 있으면 건너뜀(`--force`로 재생성, `--only <표제어>` 지원).
- API 키: 저장소 루트 `.env`의 `OPENAI_API_KEY`.

**검수 게이트**
- 빌드는 `reviewed: true` 파일만 공개.
- `build-site.py --preview <dir>`: 미검수 포함 로컬 미리보기(커밋 대상 아님, `docs/` 밖에 출력).

**`build-site.py`** (Jinja2 템플릿)
- 생성물: 인덱스(가나다순 + 인기 상징), 상징 페이지(~77), 상황 페이지(~300), `sitemap.xml`.
- 빌드 시 `docs/haemong/`를 통째로 재생성(공개 대상에서 빠진 페이지는 삭제됨).

### 3-4. 페이지 구성

- `<title>`(≤60자), meta description(aliases 일부 자연 포함), canonical, OG 태그, JSON-LD(Article, BreadcrumbList).
- 내부 링크: 같은 상징의 다른 상황, 같은 극성의 관련 상징, 상징 허브 ↔ 상황 페이지.
- CTA: 모든 페이지에 "내 꿈 직접 해몽받기" 버튼 →
  `https://play.google.com/store/apps/details?id=com.mswon.monkey&referrer=utm_source%3Dseo%26utm_campaign%3D<슬러그>`
- 디자인: 앱과 같은 다크 인디고/골드 아르누보 톤, 모바일 우선, JS 없음, 본문 17px 이상(4060 가독성).
- 하단 고지: "전통 해몽은 참고용이며 미래를 단정하지 않습니다."
- 프로젝트 사이트라 루트 `robots.txt`는 둘 수 없음 → 사이트맵을 서치콘솔에 직접 제출.

### 3-5. 검색엔진 등록 (사용자 수동, 체크리스트 제공)

- 구글 서치콘솔: URL 접두어 속성 `https://ms-won.github.io/Monkey/` → HTML 파일 인증(`docs/`에 배치) → 사이트맵 제출.
- 네이버 서치어드바이저: **github.io 하위 경로 등록 가능 여부 불확실** → 구현 첫 단계에서 확인.
  불가하면 웹 페이지 수집 요청으로 우회하거나 커스텀 도메인 재검토(사용자 결정).

### 3-6. 테스트와 측정

- pytest:
  - 슬러그 중복 없음
  - 모든 내부 링크가 실제 생성된 페이지를 가리킴
  - sitemap 항목 = 공개 페이지 집합
  - `reviewed:false` 콘텐츠가 공개 산출물에 없음
  - title ≤ 60자, 상황 페이지 title/H1이 상황명으로 시작
  - 콘텐츠 JSON 스키마 검증
- 수동: 모바일 Lighthouse SEO ≥ 90, Pages 배포 후 링크 클릭 확인.
- 측정: 구글 서치콘솔 노출/클릭, 네이버 유입, Play Console `utm_source=seo` 설치 수 → `rank-log.md`.
