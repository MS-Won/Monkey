다른 PC에서 진행하던 작업을 이어받는다.

사용자 요청: $ARGUMENTS

## 1. 최신 상태 받아오기

```
git status --short
git fetch origin
git log --oneline -5 origin/main
git rev-list --left-right --count HEAD...origin/main
```

- 로컬에 미커밋 변경이 있으면 **덮어쓰지 말고 사용자에게 먼저 보고**한다.
- 깨끗하고 뒤처져 있으면 `git pull origin main`.
- 갈라졌으면(양쪽 다 커밋 있음) 임의로 머지·리베이스하지 말고 상황을 설명하고 물어본다.

## 2. 상태 문서 읽기

이 순서로 읽는다:

1. `CLAUDE.md` — 프로젝트 규칙과 함정
2. `docs/STATE.md` — **지난 세션이 남긴 인수인계서. 가장 중요하다.**
3. `todo.md` — 작업 큐

STATE.md가 가리키는 문서가 있으면 그것도 읽는다.

## 3. 환경 점검

다른 PC라면 git에 없는 것들이 빠져 있을 수 있다. 조용히 확인만 하고, 빠진 것만 보고한다.

- 루트 `.env` 존재 여부 (**없으면 번들링이 깨진다** — `docs/HANDOFF.md` 참조)
- `node_modules/` 존재 여부
- 릴리스 빌드를 할 상황이면 `android/keystore.properties`와 키스토어 존재 여부
  (없으면 디버그 키로 폴백해 Play가 거부하는 AAB가 나온다)

## 4. 현황 보고

사용자에게 이렇게 정리해 알린다:

- **지난 세션이 한 일** — 커밋 몇 개, 무엇을
- **지금 상태** — 저장소와 외부 시스템(Play Console 심사 등) 양쪽
- **막혀 있거나 사용자 손이 필요한 것**
- **다음 할 일 후보** — STATE.md 기준, 우선순위 순

## 5. 다음 행동

- 사용자가 `$ARGUMENTS`로 할 일을 지정했으면 그것부터 한다.
- 지정하지 않았으면 다음 할 일 중 무엇을 할지 **하나를 추천하고** 확인받는다.
- STATE.md가 없거나 내용이 오래됐으면(마지막 갱신이 최신 커밋보다 한참 전이면)
  그 사실을 말하고, git 로그로 실제 상태를 재구성해 보고한다.

STATE.md에 적힌 내용이 지금 저장소와 어긋나면 **저장소를 믿고** 그 사실을 알린다.
